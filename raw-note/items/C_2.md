### 第二章 - Why Learn C?

What is C? (pros and cons)

- Pros of C
  - Full Control
  - Fast and Efficient
  - Portable
  - Foundation for Other Languages
- Cons of C
  - Manual Memory Management
  - No Safety Net
    - Compiler 不會阻止你作任何事情
  - Verbose and Prone to Bugs
  - Why Bother?
    - 學會 C 代表能用接近機器的思考模式, 在學其他東西都會更容易

C vs Other Languages

- Interpreted vs Compiled
- Garbage Collection
  - C 沒有 Garbage Collection, 優點是更好的效能, 缺點是必須自行處理
- Strong vs Weak Typing
  - 具有型別但是是 weak typing, 意味著同一個記憶體位置可以被進行型別轉換使用 (implicitly 或者 explicitly)

Is C Still Relevant in Today's World?

- Proven and Ubiquitous
- Simplicity and Control
- Performance

### 第三章 - C Fundamentals

Introduction to Variables

- Variable Names
  - 為了未來的你選擇有意義的名稱
- Variable Types
  - 告知 compiler 資料型別
  - 讓 compiler 知道需要使用多少記憶體空間, 以及如何操作
- Variable Declarations in C
  - 先宣告才能使用
  - `type name = initial_value;`
  - 必須包含資料型別, 變數名稱; 初始值是選用的
- Best Practices
  - 選用有意義的名稱

Variable Scope Rules

- 變數只會存在特定的時間內
- 被存在 RAM 中
- 由 scope 決定該變數會存在多久
- scope 也意味著一個範圍, 程式只能在這個範圍內讀取特定的變數
- How does variable scope work in C?
  - 主要分成兩類, local scope 與 global scope
- Local scope (function scope)
  - `{}` 大括號產生 local scope
- Global scope
  - 定義在函式的外部形成全域變數
  - 使用全域變數通常被視為是壞的作法 (bad practice)
  - 讓變數值難以預測, 容易造成邏輯錯誤

Introduction to Preprocessor

- What is the Preprocessor?
  - Preprocessor 是轉譯 C 程式碼到可執行檔的**第一個**階段
  - 由 `#` 符號開頭的命令, 來告知 preprocessor
- Why is Preprocessing Needed?
  - 在進入 compiler 階段之前, 需要針對 source code 去組合一些 context-aware 的資訊, 因此需要 preprocessor
  - 例如:
  - Expands macros
  - Includes external files (像是 standard libraries or headers)
  - Enables conditional compilation (有條件式的編譯)
  - Removes comments (移除 comments)
- 沒有 preprocessor 時則無法處理像是 `#include <stdio.h>`, macro definitions, 或者 `#ifdef`
- The Full Compilation Process
  - 編譯 C program 的流程
  - 1 Preprocessing, 處理 `#`
  - 2 Compilation, 轉譯程式碼至 assembly
  - 3 Assembly, 轉換 assembly 至 machine code (object files)
  - 4 Linking, 連結所有的 object files 與 libraries 形成 executable
- Common Preprocessor Directives
- `#define`, 定義一個 macro
  - 範例: `#define PI 3.14`
  - 1 常用於定義常數 constant, 2 常用於控制啟用特定功能, 例如 `#define DEBUG`
- `#undef`, 取消先前定義的 macro
  - 範例: `#undef PI`
- `#include`, include 其他檔案的內容
  - 範例: `#include <stdio.h>`, `#include "myheader.h"`
- `#if`, `#elif`, `#else`, `#endif` 用於控制編譯
  - 範例:
  - ```c
    #if DEBUG
    printf("Debug mode\n");
    #endif
    ```
- `#ifdef`, `#ifndef`, 用來檢查 macro 是否存在
  - 範例:
  - ```c
    #ifdef DEBUG
    #define LOG(x) printf(x)
    #else
    #define LOG(x)
    #endif
    ```
- `#error`, 產生 compile-time error
  - 範例: `#error "Unsupported platform"`
- `#pragma`, 指定 compiler-specific instructions
  - 範例: `#pragma once`
- `#line`, Changes the compiler’s idea of the line number and filename.
  - 範例: `#line 100 "custom_file.c"`
- `#warning`, 產生 compiler warning (GCC specific)
  - 範例: `#warning "This is a warning"`
- Summary
  - preprocessor 是 build pipeline 中不可或缺的階段
  - 理解這個功能, 讓你寫的程式有更好的 portable, maintainable, and configurable
